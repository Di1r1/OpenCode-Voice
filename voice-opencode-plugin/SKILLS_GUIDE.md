# Навыки (skills) в OpenCode Voice: подключение и эксплуатация

> **Версия:** 1.0 · **Дата:** 2026-09-17
> **Статус:** рабочий документ; описывает фактическую конфигурацию проекта
> **Область:** `.opencode/skills/`, `AGENTS.md` (таблица маршрутизации), глобальный `~/.config/opencode/`

---

## 0. Коротко (минимальный рецепт)

```sh
# 1. создать каталог навыка (имя = kebab-case, оно же в frontmatter)
mkdir -p voice-opencode-plugin/.opencode/skills/ovi-<область>

# 2. написать voice-opencode-plugin/.opencode/skills/ovi-<область>/SKILL.md (шаблон — Приложение A)

# 3. перезапустить OpenCode и проверить (обнаружение — только на старте)
#    в сессии: skill({ name: "ovi-<область>" })   → содержимое загружено
```

Затем добавить строку «задача → навык» в таблицу маршрутизации в `AGENTS.md` (раздел **Skill routing**). Без этой строки модель знает о навыке, но не обязана его грузить.

---

## 1. Как это устроено: две независимые системы

| | Ядро OpenCode (встроенный инструмент `skill`) | Плагин `@zenobius/opencode-skillful` |
|---|---|---|
| Что даёт | блок `<available_skills>` в системном промпте + инструмент `skill` | инструменты `skill_find`, `skill_use`, `skill_resource` |
| Загрузка | по решению модели, разово в диалог | «ленивая», подстановкой сообщения |
| Идентификатор | `name` из frontmatter (`ovi-plugin`) | slug из пути (`ovi_plugin`) |
| Видит наши навыки | **да** (через `skills.paths`) | **нет** (свой реестр; у нас в нём только `plannotator`) |

**Факт проекта.** Навыки `ovi-*` подключены и работают через **штатный** инструмент `skill` (проверено загрузкой `ovi-overview`). `skill_find`/`skill_use` их не показывает — это особенность отдельного плагина, а не отсутствие навыков. Автоматики нет: решение грузить навык принимает модель, увидев список в промпте; обязательность задаёт таблица в `AGENTS.md`.

---

## 2. Откуда берутся навыки (пути и приоритет)

| Источник | Путь | В проекте |
|---|---|---|
| Проектные | `<cwd>/.opencode/skills/<name>/SKILL.md` | сработает, если OpenCode запущен из корня репо |
| Глобальные | `~/.config/opencode/skills/<name>/SKILL.md` | `plannotator` |
| Дополнительные каталоги | `skills.paths` в `opencode.json` | **наши 7 навыков `ovi-*`** |
| Встроенные | поставляются с OpenCode | `customize-opencode` |

Наши навыки лежат в `voice-opencode-plugin/.opencode/skills/` и подключаются глобальным конфигом:

```jsonc
// ~/.config/opencode/opencode.json
{
  "skills": { "paths": ["/ABS/PATH/voice-opencode-plugin/.opencode/skills"] }
}
```

Правила: при совпадении имён побеждает более поздний путь; дубликаты логируются и пропускаются; **обнаружение — при запуске** OpenCode (после добавления навыка нужен перезапуск). Если `opencode` запускается не из корня репо (у нас cwd процесса — `/mnt/c/WINDOWS/system32`), проектный скан `.opencode/skills` не сработает — поэтому используйте `skills.paths`.

## 3. Анатомия навыка

```
voice-opencode-plugin/.opencode/skills/ovi-<область>/
  SKILL.md          # обязательно: frontmatter + инструкция
  references/       # опционально: подробности/примеры
  scripts/          # опционально: безопасные скрипты без секретов
```

Frontmatter:

```yaml
---
name: ovi-<область>        # ДОЛЖНО совпадать с именем каталога: lowercase, цифры, дефисы
description: Использовать когда ...   # триггеры: симптомы, имена файлов, команды
---
```

Требования: `name` — только `^[a-z0-9]+(-[a-z0-9]+)*$` (подчёркивания **нельзя**), `description` ≥ 20 символов и описывает **когда** применять (в третьем лице — текст попадает в системный промпт). Объёмные материалы — в `references/`, чтобы `SKILL.md` читался целиком.

---

## 4. Как подключить новый навык

1. **Имя.** `ovi-<область>` (префикс проекта обязателен).
2. **Каталог.** `mkdir -p voice-opencode-plugin/.opencode/skills/ovi-<область>`
3. **`SKILL.md`** по шаблону (Приложение A).
4. **Ресурсы (опционально).** `references/` — детали; `scripts/` — повторяемые команды (без секретов).
5. **Проверка после перезапуска OpenCode:** `skill({ name: "ovi-<область>" })` — содержимое подставилось; `skill_find` не обязателен (см. §1).
6. **Регистрация в `AGENTS.md`** — строка в таблице **Skill routing** (Приложение B), чтобы модель была обязана грузить навык.
7. **Практика:** прогнать реальную задачу и убедиться, что навык загружен до правок.

---

## 5. Как гарантировать загрузку

Автозагрузки нет; по надёжности:

1. **Таблица в `AGENTS.md`** (основной механизм проекта).
2. **Строка в промпте сабагента** (`.opencode/agents/<agent>.md`): «перед правками X загрузи навык `ovi-<область>`».
3. **Явная команда владельца** («загрузи навык …»).

Если навык не срабатывает — сначала правьте `description` (добавить имена файлов и симптомы), а не промпт.

---

## 6. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| Навыка нет в системном промпте/`skill` | нет перезапуска OpenCode | перезапустить |
| | каталог не подключён | добавить путь в `skills.paths` |
| | `name` ≠ имя каталога, или подчёркивания | выровнять имя |
| | `description` короче 20 символов | дополнить |
| Есть в `skill`, нет в `skill_find` | так и должно быть (разные системы) | использовать `skill` |
| Навык «перекрыт» | дубликат имени | переименовать/убрать дубль |
| Инструкция «не дочитана» | слишком большой `SKILL.md` | вынести детали в `references/` |

---

## 7. Версионирование

Навыки **версионируются** (в отличие от остального `.opencode/`). Корневой `.gitignore`:

```gitignore
voice-opencode-plugin/.opencode/*
!voice-opencode-plugin/.opencode/skills/
```

Проверка: `git check-ignore -v voice-opencode-plugin/.opencode/skills/ovi-overview/SKILL.md` (ничего не должно вывести) и `git status` (файлы видны как tracked). Новый навык просто `git add`.

---

## 8. Безопасность

- Никаких секретов в `SKILL.md`, `references/`, `scripts/` — только плейсхолдеры (`<ABS/PATH>`, `<host>`). Репозиторий публичный.
- В глобальном конфиге OpenCode есть Google API-ключ — никогда не копировать его в репо и в навыки.

---

## 9. Чек-лист «навык подключён правильно»

- [ ] каталог `.opencode/skills/ovi-<область>/SKILL.md` создан
- [ ] `name` == имя каталога (lowercase, дефисы), `description` с триггерами
- [ ] тело — пошаговая инструкция с проверяемыми командами, без секретов
- [ ] объёмные материалы — в `references/` (при необходимости)
- [ ] строка добавлена в таблицу **Skill routing** в `AGENTS.md`
- [ ] OpenCode перезапущен, `skill({ name: "ovi-<область>" })` работает
- [ ] файл виден в git (`git status`), не съеден `.gitignore`
